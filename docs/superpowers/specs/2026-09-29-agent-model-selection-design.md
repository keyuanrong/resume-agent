# Agent 模型选择与密钥保护设计

## 目标与范围

在现有 `feature/my-change` 分支上简化 Agent 设置：界面只显示“模型”和“API Key”两个输入项，首批支持阿里云百炼（北京地域）与 DeepSeek。模型选择既可使用内置常用型号，也可在选择服务商后通过该服务商的模型列表接口更新；用户必须确认最终模型，系统不能仅凭 API Key 唯一推断模型。

本次不接入智谱和火山方舟。现有简历分析、策略生成、边界岗位判断和 Boss 执行流程保持原有行为。

## 交互

- “模型”是可搜索的选择控件，候选按“百炼”和“DeepSeek”分组；初始提供 `qwen3.7-flash`、`qwen3.8-flash` 和 `deepseek-flash`。选择候选时同时确定服务商，无单独的服务商输入框。
- “API Key”是密码输入框，已有密钥仅显示“已配置”，不回显值。输入新 Key 并保存后立即清空输入框。
- 保存后，用户可在同一模型控件中点击“获取可用模型”；后端只向当前服务商查询列表，返回模型 ID 与显示名称。查询失败时保留现有选择并显示具体错误；不把静态候选伪装成 API 返回结果。
- 手工输入未知模型 ID 时要求从候选中明确选择服务商归属，避免把 Key 发送给错误的服务商。切换服务商后只使用该服务商的 Key；没有 Key 时提示输入。

## 后端结构与数据流

- 将服务商信息集中在固定注册表：服务商 ID、显示名称、Chat Completions 地址、模型列表地址、请求参数差异。客户端不得提交任意 API URL。
- 百炼沿用北京地域的 Chat Completions 地址；模型列表优先调用北京地域可用的模型列表接口。DeepSeek 使用其官方 `/models` 与 `/chat/completions`。两家列表响应各自解析为统一的 `{id, name, provider}`。
- Agent 请求使用当前策略中的服务商和模型；只向对应服务商发送该服务商的 Key。针对请求格式差异，按服务商生成参数，继续要求 JSON 输出。模型列表不自动发起简历分析或付费对话。
- `product_config.json` 仅保存服务商 ID 和模型 ID，不保存 Key。公开配置只返回当前服务商是否有 Key，不返回 Key 本身。

## 密钥保护与迁移

- 新密钥写入操作系统密钥库，服务名为 `resume-agent`，账户名为服务商 ID。项目不再把新 Key 写入 `data/secrets.json`，前端不使用 localStorage、URL 或日志保存 Key。
- 首次读取百炼旧配置时，若旧 `data/secrets.json` 中有 `qwenApiKey`，先成功写入系统密钥库，再删除旧文件；写入失败时不删除旧 Key，向用户报告迁移失败。
- 系统密钥库不可用或锁定时，保存与使用密钥均明确报错，不回退到明文文件。错误文本不得包含 Key。服务仍只监听 `127.0.0.1`。

## 验证

- 后端测试覆盖：服务商与模型绑定、列表结果解析与错误、请求路由、密钥不进入公开配置和日志、旧密钥成功及失败迁移、密钥库不可用。
- 前端测试覆盖：只有两个输入项、切换服务商不复用错误 Key、保存后清空密钥框、模型列表失败不覆盖当前选择。
- 手工验证：在无真实 Key 的情况下完成本地配置与测试；真实模型列表和推理调用需使用用户自己的 Key，并由用户在本机执行。
