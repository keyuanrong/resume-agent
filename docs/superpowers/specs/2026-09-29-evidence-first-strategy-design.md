# 简历证据优先的共用词表设计

## 目标

文字简历在手动模式和 Agent 模式走同一套本地岗位方向识别与词表生成。用户确认的岗位方向决定搜索词；简历中的技术只作为对应方向的匹配证据。Agent 仅复核本地规则难判断的职位。图片简历先用已配置模型转录文字，再进入相同的本地流程。

## 数据流

简历文字 → 本地识别候选方向 → 按选定方向生成搜索词和正反向评分词 → 用户确认 → 本地评分 → 边界职位可选 Agent 复核。Agent 不能在简历分析和策略生成阶段增添岗位、技能或经历。

## 匹配规则

- VLA、具身智能和机器人学习是 VLA 模板的岗位方向。强化学习是这个方向的技术证据，不自动生成独立的强化学习岗位搜索词。
- 技能词用于职位描述匹配，不因为简历提到它就给岗位标题加分。纯强化学习岗位得不到 VLA 标题加分；含 VLA 的在线或离线 RL 岗位仍可加分。
- 保留模型版本：`π0` 和 `π0.5` 是不同技能。只在原文出现相应型号时加入词表，评分时不能用 `π0` 命中 `π0.5`。
- 仿真验证、真机部署不自动改写为 Sim2Real。明确排除词由用户决定；模板中的相邻方向使用软扣分。
- 用户输入的技能若未在简历及所选方向的证据词中出现，显示为“未采纳的技能词”，不参与评分。
- 生成结果继续使用现有统一策略和评分接口。已保存但未确认的旧 Agent 草稿不自动启用。

## 验收

使用含 π0.5 实习、π0 项目、VLA 在线 RL 和 MuJoCo 仿真验证的简历：搜索词不含独立强化学习岗、标题正向词不含强化学习、技能词同时保留实际出现的两个模型版本、没有 Sim2Real。模拟 VLA+RL 岗位评分高于纯 RL 岗位，且本地和 Agent 模式生成同一词表。
