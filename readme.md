# Resume Agent

一个“本地控制台 + 招聘平台浏览器脚本”的求职辅助工具。用户可以使用纯手动规则，也可以让百炼或 DeepSeek Agent 分析简历、追问求职偏好并生成策略；两种模式最终都会转换成同一种策略，由平台执行层使用。

> Boss 直聘已跑通筛选和自动打招呼链路。智联招聘已跑通搜索、评分和“立即投递”，由智联发送默认招呼语和当前平台简历。前程无忧已接通搜索接口、完整 JD 评分和平台简历投递；只在自动发送、达到阈值、平台已启用且未命中七天去重时点击投递。产品不处理招聘者回复，也不额外上传或追发简历。

## 已实现

- 本地 Web 控制台：`http://127.0.0.1:8000`
- Agent 开关，明确展示服务商、模型和密钥状态
- 免费本地模式：上传 PDF/DOCX/文本简历，在本机生成个人搜索词、技能词和完整评分词库，支持修改后确认
- 手动模式：也可以不上传简历，直接填写搜索词、技能、阈值、排除词、公司黑名单和每个搜索词查看数
- Agent 模式：文字简历复用本地词表生成；图片简历先由所选模型转录文字。Agent 只在规则难判断的边界岗位上复核
- 阿里云百炼与 DeepSeek 接入；API Key 保存在本机系统密钥库
- 规则优先、边界岗位调用 Agent 二次判断；Agent 失败时回退规则结果
- 两种投递模式：筛选不发送、自动发送
- 平台能力注册表：Boss、智联、前程无忧
- 本地简历用于生成词库；自动投递使用招聘平台已有简历
- 公司名称采集、招聘机构/猎头标识、黑名单拦截、跨次去重、运行日志和处理记录
- 公司名称是所有平台的必填安全字段；识别失败时强制转人工审核
- Boss 猎头岗位会明确显示招聘机构，并与直招岗位一样进入词库评分；达到阈值后按所选投递模式处理
- Boss 搜索、岗位评分、打招呼、收到新消息后选择平台已有简历

## 安全边界

- Agent 生成的策略必须由用户确认后才生效。
- 公司黑名单、每个搜索词查看额度等硬规则不会被 Agent 绕过。
- 默认模式是“筛选不发送”，不会自动联系招聘者。
- 自动聊天默认关闭。
- API Key 保存在系统密钥库；上传的简历在被 Git 忽略的 `data/` 下。
- 文字简历分析与词表生成在本机完成。图片简历在用户主动点击“分析简历”时发送给所选模型转录；边界岗位复核会发送岗位内容和简历画像。
- Boss 自动链路只使用招聘平台已有简历，不会将本地上传的简历作为附件发送。

## 架构

```text
简历本地生成 ──┐
手动配置 ──────┼─> 统一求职策略（含个人词库） ─> 规则评分 ─> 边界岗位 Agent ─> 平台执行
Agent 生成 ────┘                                                    │
                                                       ├─ Boss（已接入）
                                                       ├─ 智联（已校准，自动沟通）
                                                       └─ 前程无忧（搜索与平台简历投递）
```

主要文件：

- `main.py`：FastAPI 接口、统一策略、评分编排、日志和控制台入口
- `product_store.py`：本地产品配置、系统密钥库和简历元数据
- `agent_service.py`：百炼及 DeepSeek 简历分析、策略生成和边界岗位判断
- `model_providers.py`：服务商固定地址和模型列表查询
- `local_strategy_service.py`：免费本地简历分析、岗位模板匹配和个人评分词库生成
- `resume_service.py`：简历保存与文本/图片读取
- `platforms.py`：平台能力和接入状态注册表
- `core.py`：现有规则评分逻辑
- `config.py`：旧配置兼容与底层评分参数
- `web_script.js`：Boss 直聘 Tampermonkey 执行器
- `static/`：产品控制台页面
- `user_config.example.json`：旧配置和底层运行参数模板
- `docs/ARCHITECTURE.md`：平台适配接口与扩展约定

## 快速开始

### 1. 安装依赖

建议使用 Python 3.10 或更高版本以及虚拟环境：

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Windows 激活虚拟环境：

```bat
.venv\Scripts\activate
```

### 2. 准备底层配置

```bash
cp user_config.example.json user_config.json
```

控制台确认策略后会覆盖搜索词、阈值、公司黑名单和每个搜索词查看数。每次点击“开始”后，每个搜索词独立累计查看岗位数，翻页也计入同一额度；旧版每日上限、城市、岗位类型、最低薪资和固定招呼语设置不再生效。`user_config.json` 仍负责浏览器等待时间、Boss 平台简历序号和底层评分参数等高级配置。

### 3. 启动服务

```bash
python main.py
```

然后打开：

```text
http://127.0.0.1:8000
```

### 4. 选择模式

免费本地模式：先在“简历资产”上传带可复制文字的 PDF、DOCX、TXT 或 Markdown，在手动规则页选择简历并点击“本地分析并生成”。系统会列出多个候选职业方向，用户必须选择自己真正想投递的方向，再生成该方向的词库。系统不会调用 Agent，也不会把简历上传到第三方。检查搜索词、技能词、排除词以及“评分词库”高级项后，点击“保存并启用手动策略”。

纯手动模式：不上传简历也可以直接填写关键词、技能、阈值、排除项、公司黑名单和每个搜索词查看数。保存时系统会根据这些内容构造个人评分词库，不再使用仓库里的固定 VLA 词库。

Agent 模式：

1. 开启 Agent。
2. 点击“阿里云百炼”或“DeepSeek”，输入该服务商的 API Key。
3. 输入 Key 后等待模型列表自动出现，从“模型名称”下拉框选择一个模型。查询失败时可点击“重新查询模型”。
4. 保存 Agent 设置；Key 存入系统密钥库，页面立即清空 Key 输入框。
5. 上传并选择一份简历，点击“开始分析”。
6. 本地解析文字简历后确认主要岗位方向、目标岗位、重点技能和明确排除的方向；这些答案会影响搜索词和匹配词表。城市、薪资、工作性质等职位信息由招聘网站提供，不再向用户追问。仅图片转录和边界岗位复核调用模型。

默认模型名是 `qwen3.8-flash`。旧版 `data/secrets.json` 的百炼 Key 会在首次读取时迁移到系统密钥库，确认写入成功后才删除旧明文文件。系统密钥库不可用时，页面会报错，不会重新保存为明文。模型列表只用于展示可选 ID；实际可调用范围仍以服务商账户权限为准。

百炼北京地域的官方模型列表接口可能要求业务空间 ID。如查询提示此项，可在启动服务前运行 `export DASHSCOPE_WORKSPACE_ID=你的业务空间ID`；模型页面仍只需填写模型名称和 API Key。

### 5. 安装 Boss 浏览器脚本

把 `web_script.js` 的内容粘贴到 Tampermonkey，新建并保存脚本。保持本地后端运行，然后登录并打开 Boss 直聘岗位页。

### 6. 测试智联和前程无忧完整链路

把 `multi_platform_test.user.js` 作为一个独立脚本安装到 Tampermonkey。智联和前程无忧现在使用与 Boss 相同的左下角控制面板和操作方式，包含“清空、开始/暂停/继续、收起/展开”，并读取同一份多关键词策略与每词查看额度。它会测试登录识别、搜索、列表滚动、岗位详情、公司和 JD 提取、去重、规则/Agent 评分、简历与联系动作计划和运行日志。

测试两个平台时，把投递方式设为“筛选不发送”；系统会完成读取、评分和记录，但不会执行沟通、申请、简历发送或自动回复。

智联自动执行前，将投递方式设为“自动发送”并启用智联平台。达到阈值且通过黑名单与去重检查的岗位会点击“立即投递”；默认招呼语和简历由智联随投递一起发送，脚本不会再重复发送第二条招呼。所有平台都不处理后续回复，也不额外上传或追发简历。

登录智联或前程无忧并进入岗位列表页，点击左下角“开始”。脚本会像 Boss 一样轮换已保存的搜索关键词，并在各关键词达到查看额度或岗位列表结束后停止。第一次运行主要用于校准两个网站登录后的真实 DOM；任何失败都会显示具体阶段，并写入 `/job-report`。

## 投递模式

- `筛选不发送`：评分和记录岗位，不自动打招呼。
- `自动发送`：合格岗位自动打招呼，并启用已有的 Boss 新消息检测/平台简历发送流程。

第一轮使用建议选择“筛选不发送”，先观察处理记录和评分结果，再决定是否启用自动发送。旧版“审核后发送”设置会安全迁移为“筛选不发送”。

控制台只保留“投递方式”：选择“筛选不发送”时只记录结果；选择“自动发送”且平台已完成适配、所有硬规则通过时，才可能执行真实动作。

## Agent 的职责

Agent 只负责：

- 从简历提取候选人画像。
- 提出少量求职偏好问题。
- 生成搜索词、排除项和阈值。
- 对规则分数处于边界区间的岗位做二次判断。

Agent 不负责：

- 登录招聘平台。
- 绕过平台限制或用户硬规则。
- 直接操作简历上传控件。
- 未经确认修改账号或自动回复招聘者。

## 平台扩展

`GET /api/platforms` 会返回每个平台的接入状态和能力，例如是否支持搜索、公司名、首次附件、PDF、图片和平台简历。

增加平台时，应按 [平台适配设计](docs/ARCHITECTURE.md) 实现同一组动作，再对真实登录页面进行人工校准与小流量验证。页面变化可能导致浏览器自动化失效，因此平台不能仅凭接口占位就标记为“已接入”。

## 本地数据与 Git

以下内容默认不会提交到仓库：

- `data/`：Agent 配置、API Key、上传的简历
- `user_config.json`：个人运行配置
- `job_decisions.jsonl`、`job_actions.jsonl`：执行记录
- 个人简历文件

公开仓库里只保留示例配置。提交代码前可用 `git status` 确认没有隐私文件进入暂存区。

## 当前限制

- 智联招聘已完成真实列表/详情页校准，选择“自动发送”时点击“立即投递”；前程无忧使用登录态搜索接口读取完整 JD，并在满足阈值时点击平台“投递”按钮。两者都使用招聘平台已有简历，不上传本地附件，也不处理招聘者回复。
- Boss 的 PDF/图片附件发送尚未完成可靠校准；当前可自动选择招聘平台已有简历。
- 页面自动化依赖招聘网站 DOM，网站更新后可能需要调整选择器。
- 免费本地模式不包含 OCR；扫描版 PDF 和图片简历请改用可复制文字的文件，或者在明确同意数据发送后使用 Agent 模式。
- 本地岗位模板当前覆盖销售、市场运营、客服售后、人力行政、财务会计、VLA/具身智能、AI应用、后端、前端、数据、机器学习、DevOps、产品、嵌入式和机械自动化；无法识别时会要求用户手动填写，不会假装生成可靠策略。
- 使用招聘平台自动化前，请自行确认并遵守对应平台条款、频率限制和适用规则。
